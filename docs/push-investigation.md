## 修正内容

- `push-client.js` に通知処理を集約。従来の設定キー・端末トークンを再利用し、タイマーやキャラクターの保存領域を消さない。
- 設定の `days` と `hours` を両方送信。旧公開版の「期限当日（days=0）」も維持する。
- タイマー追加・編集・リセット・削除が通る既存の `save()` から即時同期を開始。画像やキャラクター情報は送信しない。
- 同期は直列化し、端末の世代番号をD1で比較。終了時のkeepalive送信が古い通信と前後しても、新しい予定を保護する。オフライン・HTTP失敗は未同期として保持し、オンライン復帰・再表示で再送する。
- D1の購読更新・予定作成・不要予定の取消を1回のトランザクションにする。上限超過・不正な入力は全体を拒否し、黙ってタイマーを切り捨てない。
- 不要予定は `cancelled_at`、無効な購読は `invalidated_at` で保持する。通知停止や404/410でも履歴を削除しない。
- Cronは期限付きリースを取得して送信し、Pushサービスの2xx受付後にだけ `sent_at` を記録。Worker停止後の期限切れリースを回収する。
- ネットワーク障害、408/425/429、5xxは指数バックオフで再試行。Retry-Afterを尊重し、最大8回。400/401/403/413等は恒久失敗として記録する。
- 一時的な通信断で1分の受付猶予を過ぎても、期限内の予約は保持する。先行通知の有効期限はタイマー期限と予定時刻+24時間の早い方。当日通知は予定時刻+24時間。作成前に過ぎていた通知時刻は予約しない。
- Web Pushの暗号化・署名に既存のweb-pushを使い、送信はWorkersのfetchを使用する。TTL、high urgency、安定したtopicを設定する。
- SWは毎回 `event.waitUntil` 内で通知を表示する。同じtag・renotify=falseで同じ通知を置換し、端末で表示APIが成功してからreceiptを返す。
- `displayed_at` は表示APIの完了確認であり、ユーザーがバナーを見た証明ではない。receiptの通信失敗でも通知表示を妨げない。
- SWの購読変更イベントでは、保存した端末IDと旧endpointを照合して購読だけを更新。通常の再表示時にも購読を再確認する。許可済みのボタンは無効化し、許可処理や通常保存で既存の購読を作り直さない。
- Manifestの参照とiOSのWebアプリメタ情報を追加。SWとクライアントはキャッシュを再検証する。
- `build-info.json` にGitリビジョンと配信ソースのハッシュを出力。`/api/push/key` はプロトコル番号とWorkerバージョンIDも返し、次回から配信の一致を確認できる。

WebKitは、Pushイベントで通知を表示しないと購読を取り消す場合がある。
そのため、端末側で受信を黙って捨てる重複排除は採用しない。
送信成功直後・DB記録前にプロセスが落ちる場合など、Web PushとD1の間で厳密な一度限りの配信は保証できない。
DBの一意ID・リース・topic・通知tagで重複を抑える。既に表示・消去した後の再配信までは完全に防げない。

## Safari向けホーム画面追加ガイド

- iPhone/iPadのSafariをブラウザーとして開いた初回に、ホーム画面への追加手順をモーダルで表示。`navigator.standalone` と `display-mode: standalone` を確認し、Webアプリ起動では表示しない。PCや他ブラウザーも自動表示の対象外。
- 「今後表示しない」はブラウザー専用の `arkManager_install_guide_dismissed_v1` に保存して閉じる。「あとで」や×はその回だけ閉じる。ストレージが使えない場合も閉じる操作は妨げず、キャラ・タイマー・通知設定を変更しない。
- 添付の共有マークの形をbuilt-in imagegenで透過画像にし、`safari-share-symbol.png` として本文にインライン表示。通知設定の説明文も同じ画像を使う。画像生成の指示は「上部中央が開いた角丸の四角と上向き矢印を、均一なシアンの線で描く。線以外と内側を完全透過し、背景・影・ノイズを加えず、小さい文字サイズでも読めるよう中央へ大きく配置」。表示時はCSSで白にそろえる。
- 操作手順は[AppleのiPhoneユーザガイド](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)を確認。共有が見当たらない場合のメニュー経由と、「Webアプリとして開く」が表示された場合の案内を含める。
- 自動テスト76件でSafari/iPad判定、Webアプリでは非表示、抑止の永続化、一時的な終了、ストレージ失敗時の終了を確認。iPhone実機の表示・ホーム画面への追加・通知到達は未検証。

## 石画像の配信形式・建材の1行表示・自由入力の種類画像

- 石画像のPNGを検査し、画像の読み込み・8bit RGBA・透過が正常であることを確認した。iPhoneの非表示は手元では再現できていない。対策として参照先を `timer-material-stone.webp` に更新し、PNGの2,631,042バイトから1,576,508バイトへ軽量化。可視ピクセルとアルファの差分が0であることを比較した。
- 建材の選択は5列グリッドとし、320px幅でも画像と名称が1行に収まるよう調整。石の一覧画像と選択ボタンは同じWebPを使う。
- 自由入力を選ぶと「一覧右側の画像」を選択・変更・取り外せる。マップ画像と別の `customTypeImage` に保存し、一覧右側へ表示。選んだ画像はアスペクト比・透過を保って最大256pxのPNGにする。既存の画像なしタイマーもそのまま利用できる。
- 画像の読み込み中は保存を待ち、閉じる・別の画像を選ぶ・取り外す操作後に古い読み込み結果が上書きしないよう制御する。画像だけの編集では期限を変更しない。
- 引き継ぎにも種類画像を含める。埋め込みのPNG/JPEG/WebP/GIF/AVIFだけを受け付け、外部URL・SVG・不正な型は保存前に拒否する。通知の同期データに画像を含める変更はない。
- 静的検証と自動テスト81件を通過。ブラウザーで320/390pxの建材1行表示、石の読み込み、画像の選択・縮小・保存・再編集・取り外し、マップと期限の保持を確認。iPhone実機の石表示と既存ホーム画面アイコンの更新は未検証。

## タイマー一覧から直接編集・期限とメモの表示

- 一覧カードのタップで編集画面を直接開き、中間の詳細画面を廃止した。編集画面は毎回先頭から表示する。詳細画面にあった削除操作は編集画面へ移し、確認後だけ対象のタイマーを削除する。一覧右側のリセットと並び替えは維持する。
- 一覧に曜日付きの期限日時を表示し、登録済みのメモだけを改行を保って表示する。メモはHTMLとして解釈されないようエスケープし、カードの高さを内容に合わせる。320px幅でも期限・長期間の残り時間・メモがカード外へはみ出さない。
- アイランドの標準マップ画像だけ、枠線を外して表示範囲を2%拡大し、縁を切り取る。地図とピンを同じ面で拡大するため地形とピンの位置関係を保つ。元の画像ファイル、保存済みの座標、期限、アップロードした独自画像は変更しない。
- 自動テスト85件と静的検証・ビルドを通過。ブラウザーで320/390px幅、カードからの直接編集、期限・複数行メモの表示、トリミング後のピンドラッグと座標一致、未保存のピン変更の破棄、削除キャンセル、再編集時の先頭表示を確認した。iPhone実機の表示と通知受信は未検証。

再現確認：メモがあるタイマーの一覧カードで期限とメモを確認し、タップして直接「タイマー編集」が開くことを確認する。時間を変えずにメモを保存し、期限が保持されることを確認する。アイランドの地図でピンを動かして座標の変化を確認し、保存しないで閉じた後は元の位置に戻ることを確認する。「タイマーを削除」の確認をキャンセルした場合は、タイマーが残る。

## タイマー用マップ画像5枚の差し替え

- 添付順にアイランド、アストレオス、ロストコロニー、アベレーション、ラグナロクの標準画像へ適用した。`timer-map-{island,astraeos,lost-colony,aberration,ragnarok}.jpg` は添付JPEGの無加工コピーで、元ファイルとのハッシュ一致を確認している。新しいURLを使い、古い画像キャッシュとの混在を避ける。
- 新しいアイランドには白い縁がないため、前回の2%拡大を外して画像全体を表示する。座標系と保存値は変更しない。既存タイマーは標準画像だけ切り替わり、期限・メモ・ピン座標・独自にアップロードした画像を維持する。旧画像ファイルも残す。
- 自動テスト85件、静的検証、ビルドを通過。ローカルブラウザーの390px幅で5枚すべての選択・表示、既存のアイランドの一覧表示、編集を保存せず閉じた後の期限・マップ・件数の保持を確認。ローカルWorkersの画像配信検証に5枚のHTTP 200応答を追加した。iPhone実機は未検証。

## 本番反映時の手順

1. 上記の本番バージョン・ソース・Cron・D1のバインド先を反映直前にも確認する。push-developmentを参照する自動デプロイの有無も確認する。
2. 本番D1のバックアップと、現在のWorkerバージョンを保存する。バックアップには端末の購読情報を含むため、Gitやpublicには置かない。
3. `PRAGMA table_info` と `d1_migrations` の状態を再確認する。既存スキーマが本記録と一致する場合、追加だけのマイグレーションを適用する。
4. Worker・HTML・クライアント・SWを同じ修正ソースからまとめてデプロイする。VAPIDキーは再生成せず、既存シークレットを維持する。
5. `/build-info.json` と `/api/push/key` を確認し、WorkerのDBバインドと1分Cronを再確認する。
6. 既存のホーム画面アプリを開き、通知設定を保存して既存タイマーの予定を同期する。アプリの削除やSafariデータ消去は行わない。

承認後に実行したコマンド：

```sh
pnpm exec wrangler d1 migrations apply ark-manager-push --remote
pnpm deploy
```

マイグレーションは列・索引の追加とexpires_atの補完のみ。DROP/DELETEは含まない。
ロールバック時は旧Workerバージョンへ戻せるが、旧版の不具合も戻る。追加した列は残す。

## iPhone実機の検証手順（未検証）

1. iOS 16.4以降のホーム画面Webアプリを使い、端末の通知設定でARK Managerを許可する。集中モード・通知要約・音量・通信状態も記録する。
2. 修正版を再読み込みし、通知設定で1時間前/2時間前を保存する。保存後に設定画面が閉じることと、未同期エラーがないことを確認する（保存完了メッセージは表示しない）。
3. 1時間3分のテストタイマーを作成し、1時間前を選ぶ。約3分後の予約がD1にあることを確認し、アプリを完全に閉じて画面ロックする。
4. 同様に2時間3分のタイマーと2時間前でも試す。Cronは分単位なので秒単位の定刻配信ではなく、通常は次のCron実行＋Pushサービス・端末の遅延になる。
5. D1でdue_at / attempts / last_status / sent_at / displayed_atを確認し、ロック画面に届いた時刻と照合する。sent_atのみでは実機配信成功としない。
6. アプリを開いて編集・リセットし、旧予定が取消、新予定が登録されることを確認。削除、通知時刻変更、OFF、再ONも検証する。
7. 保存直後に閉じる、保存中に通信を切る、オフラインのまま編集して再開する、複数のタイマー、通知タップで復帰を試す。
8. 集中モード、端末オフライン、再起動後などは条件を分けて記録する。通信がない状態でサーバー未保存の新規時刻を、閉じたアプリから配信することはできない。

本番のApple Push受付、iPhone完全終了後の通知到達、iOS上の購読更新イベント、バナー・音・集中モード下の動作は未検証。
