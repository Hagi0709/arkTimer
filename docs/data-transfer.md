# データ引き継ぎ

キャラ一覧の下、またはタイマー画面の「データ引き継ぎ」から利用できます。

## 使い方

1. 移行元で「引き継ぎファイルを書き出す」を押し、JSONファイルを保存する。
2. AirDropやファイルアプリなどで移行先へ渡す。
3. 移行先で「引き継ぎファイルを選ぶ」を押して読み込み、追加件数を確認する。
4. 「この内容を追加する」を押す。
5. 通知を使う場合、移行先のホーム画面Webアプリで通知を許可し、通知設定を保存する。

引き継ぐ内容：キャラ情報、見た目・インプラント画像、トライブ所属、レベル上限解放・難易度、ノート取得状況、タイマーと画像・座標・期限・並び順、マップ・サーバー設定、レベル上限設定、通知のタイミング。

通知許可・Push購読・端末トークン・同期履歴は端末固有のため含めません。既に通知設定がある移行先では、その端末の通知設定を保持します。新しい端末では通知をOFFとして通知タイミングだけ読み込みます。元の端末の通知は自動では停止しません。

## データの保護

- IndexedDBとlocalStorageを読み取り、1つのローカルファイルにまとめます。サーバーへのバックアップアップロードはありません。
- 既存レコードは削除・上書きしません。同じIDは移行先を優先し、繰り返し読み込んでもキャラ・タイマーが増えません。
- マップ・サーバーは組み合わせで重複を除きます。異なる内容の同一IDのレベル条件は両方保持し、追加するキャラの参照先を調整します。
- 不正な形式・重複ID・未対応バージョン・外部画像URL・不正なデータ型を保存前に検証します。最大100MBです。
- IndexedDBへはaddのみのトランザクションで追加し、容量不足やID競合で失敗した場合はlocalStorageの書き込みを戻します。他タブが後から変更した値は上書きしません。
- IndexedDBとlocalStorage間にはブラウザー横断の原子的コミットがないため、処理中のOS強制終了までを保証する構成ではありません。元ファイルを残し、完了後の件数を確認してください。
- タイマーの開始・期限は変更しません。取り込み後は既存の通知同期処理へ最新の一覧を渡します。

## 検証

`pnpm check`、`pnpm test`、`pnpm build`、`pnpm deploy:dry`。

自動テスト：画像等の往復、機密情報の除外、既存編集の保持、重複読み込み、レベル条件の競合、壊れたファイルの拒否、IndexedDBの追加、容量不足・競合時のロールバック、localStorageフォールバック。

ブラウザーではファイルを読み込み、キャラ・タイマーの反映後に書き出し、再読み込み時の重複防止を確認します。実機ではiPhoneのファイル保存・AirDrop・別のホーム画面Webアプリでの読込、写真の表示とタイマー期限、移行先での通知許可を確認してください。iPhone実機での確認は未実施です。

## 通知画面の変更

許可済み・ブロック済みの許可ボタンは無効化して文言を変更します。準備中・許可処理中も連打できません。成功時のサーバー保存メッセージは表示せず、保存中・未同期・失敗の案内は保持します。画像の保存・追加成功トーストも表示しません。
