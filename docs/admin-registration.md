# 管理画面

ご本人だけが利用する前提で追加した機能です。同意確認や共有設定の画面は設けず、通知対応版を開いた端末の登録内容を自動同期します。

## 開き方

1. 通知対応版 `https://ark-manager.arktools.workers.dev/` を開く。
2. 上部のARK Managerロゴを10回連続でタップする。他の場所やボタンへのタップ、画面からの離脱、2秒を超えるタップ間隔で回数をリセットする。
3. 管理用パスワードを入力して「開く」を押す。
4. 端末を選ぶと詳細画面でキャラとタイマーの内容を表示する。「端末一覧」で一覧の元の位置に戻れる。

各端末で更新版を一度開く必要があります。以前のバージョンだけを使っている端末のキャラやタイマーを後から取得することはできません。GitHub Pages版では同期・管理APIを利用できません。

## 表示と同期

- キャラ名、レベル、在住マップ、サーバー番号、レベル上限解放・ボス難易度、ノート取得状況、トライブ所属を表示する。
- タイマー名、マップ、サーバー番号、種類・建材、座標・ピン表示、メモ、開始・期限、通知設定を表示する。
- 通知の登録・配信状態は取得・表示しない。通知用トークンとの紐づけや端末の通知許可状態の同期も行わない。旧版で保存された通知状態も管理APIから返さない。
- 画像・EOS ID・Steam Name・インプラント番号は同期しない。Pushのendpoint、暗号化キー、生の端末トークンも管理APIから返さない。
- 端末ごとにランダムな同期用トークンをローカル保存し、サーバーにはそのハッシュだけを保存する。通知用トークンとは分離する。
- 起動・復帰と記録変更後に最新内容を同期する。オフラインでは未同期を保持して再送し、古い世代の同期で新しい内容を上書きしない。同期失敗は元の端末データの保存を妨げない。
- 登録内容は端末ごとの最新1件だけを保持し、最終同期から30日で削除する。元の端末データや従来の通知履歴は削除しない。
- 1端末あたりキャラ100件、タイマー200件、リクエスト500KBまで。超過時は同期せず、管理画面で未同期として表示する。

## 認証

- ロゴのタップ操作は入口だけを制御する。登録内容の取得APIはサーバー側の認証を必須にする。
- パスワードのSHA-256をCloudflareシークレット `REGISTRATION_ADMIN_PASSWORD_HASH` に設定する。パスワードや照合値をHTML・配信JavaScriptに埋め込まない。
- 15分に同一IPで5回、全体で30回まで照合できる。超過時は429と待機時間を返す。
- 認証成功後はランダムな30分のセッションを発行する。Cookieは `__Host-` 接頭辞、Secure、HttpOnly、SameSite=Strict。サーバーにはCookieのハッシュだけを保存する。
- 閉じた時はログアウトし、画面内の取得データも消去する。セッション期限切れは再入力へ戻す。他サイトからのAPI呼び出しを拒否し、取得内容はキャッシュしない。

## 追加構成と検証

`0003_admin_access.sql` はセッション・照合制限、`0004_registration_snapshots.sql` は登録内容用のテーブルだけを追加する。既存のsubscribers/alertsには変更を加えない。

自動テスト144件とローカルWorkers＋D1で、10回連続タップと中断時のリセット、端末詳細への切り替え・一覧復帰・読み込み中の復帰、パスワード照合、連続試行制限、セッション期限・ログアウト、未認証拒否、通知状態の除外、古い同期の拒否、保持期限、オフライン再送、既存通知機能を検証した。今回の実行環境では操作可能なブラウザーがなく、iPhone実機と画面の操作確認は未実施。
